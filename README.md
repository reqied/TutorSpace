# Точка — кабинет репетитора

ASP.NET Core 10 Minimal API, EF Core, PostgreSQL 17, React 19, TypeScript, KaTeX, SignalR, Docker Compose и Nginx.

## Обновляешь уже запущенный сайт?

Открой **UPDATE.md**. Сохрани свой `.env`, используй ту же папку проекта и сделай резервную копию через `backup.ps1`. Данные обновляются автоматически; удалять базу или тома не требуется. Dockerfile использует Alpine-образы .NET, проверенные при запуске на твоём компьютере.

## Первый запуск с Docker на Windows

Нужен работающий Docker Desktop с Linux-контейнерами. Открой PowerShell в папке `tutor-space`:

```powershell
powershell -ExecutionPolicy Bypass -File .\init.ps1
notepad .env
docker compose up -d --build
```

Замени `TUTOR_EMAIL` в `.env` на свой email. Пароли скрипт сгенерирует. Адрес сайта: **http://localhost:8080**. Вход: `TUTOR_EMAIL` и `TUTOR_PASSWORD`. Используй именно localhost, чтобы Origin совпал с настройкой.

Если `.env` уже существует, повторная инициализация не нужна. Логин репетитора создаётся один раз в базе: изменение пароля в `.env` позже не меняет существующую учётку.

## Первый запуск на Linux/macOS

```bash
sh init.sh
nano .env
docker compose up -d --build
```

Для локального запуска без Docker остались скрипты и инструкция `START-WINDOWS.md`.

## Возможности

- Репетитор создаёт учеников с email и паролем, редактирует их контакты. Ученик видит только свои материалы, занятия и результаты.
- Расписание: дата/время, продолжительность, стоимость, ручные отметки «Проведено» и «Оплачено». Отображение времени — Екатеринбург UTC+5, хранение в базе — UTC.
- Библиотека по разделам: уроки и домашки с общей теорией и несколькими задачами. Задачи переставляются и копируются в другие материалы. Готовый материал назначается нескольким ученикам с независимыми результатами.
- Каждая задача имеет условие, ответ, решение и отдельный переключатель автопроверки. Ответ и решение получает только репетитор. Ученик сдаёт задания по одному; короткие ответы можно проверять автоматически, остальные проверяет репетитор с комментарием.
- Блоки кода с языком, сохранением отступов и копированием: теория, условия, решения, ученические ответы и карточки. Код отображается, не выполняется. LaTeX через KaTeX, текст, ссылки и предпросмотр.
- Наборы карточек с лицевой/оборотной стороной, назначением ученикам, режимом переворота, отметками «Знаю»/«Повторить» и сохранением прогресса. Репетитор видит прогресс каждого ученика. Повторение незнакомых карточек.
- PDF и изображения открываются внутри сайта; PPTX/DOCX скачиваются. Для встроенного просмотра презентации используй экспорт в PDF. Лимит файла — 20 МБ.
- Совместная доска отдельно для занятия. Штрихи сохраняются и передаются через SignalR. При конфликте версий последний конфликтующий штрих отклоняется, свежая версия загружается с сервера; штрих нужно повторить.
- Очередь Telegram/VK: новые занятия и назначения, результаты ручной проверки, напоминание за час. Реальная отправка требует токенов и привязки чатов.

## Основные файлы

`backend/Program.cs` — вход, ученики, расписание, файлы, доски. `LearningEndpoints.cs` — материалы/задачи, назначения, проверка и карточки. `Models.cs` — сущности и связи. `SchemaUpgrade.cs` и `Schema/002.sql` — обновление прежней базы. `NotificationWorker.cs` — уведомления.

`frontend/src/App.tsx` — кабинет; `MaterialEditor.tsx` — уроки и задачи; `TaskList.tsx` — сдача/проверка; `FlashCards.tsx` — карточки; `TextEditor.tsx` и `Content.tsx` — ввод/отображение текста, формул и кода; `Board.tsx` — доска.

## Проверка запуска

```powershell
docker compose ps -a
docker compose logs --tail=80 api web db
```

Статус db должен быть healthy, api/web — Up. Первый запуск может занять несколько минут из-за скачивания образов и зависимостей.

## Боты

Telegram: создай бота у BotFather, задай `TELEGRAM_BOT_TOKEN` в `.env`. Ученик сначала отправляет `/start` боту; затем его chat_id из `getUpdates` нужно указать в профиле ученика. Сам бот первым переписку не начинает.

VK: включи сообщения сообщества, создай ключ с правом отправки сообщений, задай `VK_BOT_TOKEN`. Ученик разрешает сообщения и пишет сообществу; peer_id личного диалога укажи в профиле ученика. Для исходящих уведомлений Callback API не нужен.

После изменений выполни `docker compose up -d api`. Worker проверяет очередь раз в 30 секунд, пробует отправить до 5 раз. Отдельно запоминается отправка в каждом канале. Pending-сообщения без привязки ждут подключения. При неопределённой сетевой ошибке Telegram может повторить сообщение; у VK фиксированный random_id.

Токены не добавляй в Git. В локальном режиме без Docker конфигурация находится в `backend/appsettings.Local.json`. Реальные боты без пользовательских токенов не тестировались.

## Хранение и резервные копии

Том `postgres_data` — база. Том `app_data` — файлы и ключи cookie. В Docker задан `DATA_DIRECTORY=/data`, локально используется `backend/App_Data`. `docker compose down` сохраняет тома; **down -v удаляет их**.

На Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\backup.ps1
```

Копии содержат персональные данные и секреты. Храни их вне репозитория и отдельно от сервера. Для Linux можно использовать pg_dump и архив `/data`; при согласованной копии останови API, чтобы файлы не менялись.

## Размещение на сервере

Скопируй исходники в постоянную папку, настрой `.env`, выполни `docker compose up -d --build`. По умолчанию web слушает `127.0.0.1:8080` только на сервере. Для проверки со своего ПК:

```bash
ssh -L 8080:127.0.0.1:8080 user@SERVER_IP
```

Открой http://localhost:8080 после подключения. Для постоянного доступа настрой DNS домена и внешний Nginx. Шаблон — `deploy/host-nginx.conf`: замени `tutor.example.ru`, проверь `nginx -t`, перезагрузи Nginx и выпусти сертификат Certbot. В `.env` укажи `PUBLIC_ORIGIN=https://YOUR_DOMAIN` без завершающего слеша и `APP_ENVIRONMENT=Production`, затем пересоздай API.

Если 80/443 заняты контейнером Nginx Blueprint, добавь новый server в существующий proxy с общей Docker-сетью. Не запускай второй Nginx на занятых портах и не останавливай Blueprint. `127.0.0.1` внутри proxy-контейнера относится к нему самому.

Production-cookie работает только по HTTPS. Разработка по HTTP предназначена для localhost/SSH-туннеля. Автоматического деплоя на твой сервер из этого чата нет.

## Проверки и ограничения

Команды и результаты описаны в `TESTING.md`, тесты API — в `tests/`. Проверены прежние сценарии, новые задания/карточки и переход с предыдущей базы без потери данных. Docker Engine в среде подготовки отсутствует, поэтому новый Compose целиком здесь не запускался.

Один репетитор и его ученики, без регистрации новых репетиторов. Короткие ответы сравниваются без учёта регистра, пробелов по краям и различия десятичной точки/запятой; математическое сравнение формул не реализовано. Оплата — ручной учёт, без платёжного шлюза. Карточки без интервального планировщика. Нет истории версий доски и восстановления пароля репетитора. Изменение пароля ученика пока не отзывает ранее выданные cookie до выхода/истечения срока. Изменения общего материала действуют на все его назначения; результаты автоматически не переоцениваются.
